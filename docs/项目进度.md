本文档用于同步当前仓库在 2026-06-18 的实际状态，作为中文版长篇进度说明。

## 1. 当前一句话状态

TaskFlow 现在已经不是单纯的任务流转练习骨架，而是一个具备以下内网 MVP 交付基线的 Go + React 任务协作系统样板：

- 任务状态机闭环
- memory / mongo 双驱动
- 正式 JWT 鉴权
- refresh token 轮转
- 密码重置
- 账号禁用
- 会话吊销
- 请求级结构化日志
- request / trace / span id
- identity / rate-limit / idempotency 指标
- `/health`、`/livez`、`/readyz`、`/metrics`
- Mongo 版本化 migration
- Mongo 共享限流与幂等键
- 软删除与审计保留
- 最小前端工作台（登录、任务列表、新建任务、任务详情、我的信息）
- 内网 bootstrap / 验收 / 发布检查清单
- Docker 部署、Compose 本地栈、CI、基础安全审计脚本、基础压测脚本、基础回滚脚本
- Go 1.25.11 运行时基线

换句话说，仓库已经从“能跑的业务状态机”推进到“可部署、可演示、具备基础验证闭环的内网 MVP”阶段。

## 2. 已完成能力

### 2.1 业务域能力

- 任务创建、查询、更新、领域驱动软删除（`MarkDeleted` + 审计，无仓储层 `Delete` 捷径）
- 分配任务时校验被指派者存在且 `active`
- 从 Mongo 读取任务状态时经 `ParseStatus` 校验
- 动作型生命周期接口：
  - `assign`
  - `start`
  - `submit`
  - `reject`
  - `approve`
  - `close`
  - `cancel`
  - `reactivate`
- `TaskRecord` 留存协作记录
- `AuditLog` 留存关键状态与请求元数据

### 2.2 账户与认证能力

- `IdentityService.Authenticate` 统一承载密码登录校验（Handler 不再直接比对密码）
- `Account.Disable` 封装账户禁用规则
- Mongo 模式下 refresh 轮转、密码重置确认、账户禁用走事务
- owner 可通过 `POST /users` 创建成员；匿名公开注册在内网模式下默认关闭
- `GET /users?active=true` 支持 owner 列活跃用户并供前端分配下拉复用
- `POST /auth/login` 密码登录
- `POST /auth/refresh` refresh token 轮转
- `POST /auth/password-reset/request` 发起密码重置
- `POST /auth/password-reset/confirm` 完成密码重置
- `POST /users/:id/disable` 禁用账号
- `POST /users/:id/revoke-sessions` 吊销用户 refresh sessions
- `GET /me` 获取当前用户

生产模式下：

- 使用 JWT access token
- refresh token 为持久化的 opaque token
- 禁止依赖 `X-User-ID` / 旧 plain token fallback

开发模式下 `DEV_MODE=true`：

- 仍保留 seeded 默认用户
- 仍允许 `X-User-ID`
- 仍允许旧 plain token fallback
- 密码重置接口会回显 `reset_token`，便于本地验证

### 2.3 前端与内网交付能力

- `web/` 已提供最小工作台：登录、任务列表、新建任务、任务详情、我的信息
- `TaskDetailPage` 已拆分为头部、动作区、基本信息、时间线与异步加载逻辑
- 前端已接入最小自动化校验：`lint`、`test`、`build`
- 内网交付文档已收口为：
  - `INTRANET_RUNBOOK.md`
  - `ACCEPTANCE_TESTING.md`
  - `INTRANET_OPS.md`
  - `INTRANET_RELEASE_CHECKLIST.md`
- 内网辅助脚本已包括：
  - `scripts/bootstrap_users.sh`
  - `scripts/backup_mongo.sh`
  - `scripts/restore_mongo.sh`
  - `scripts/compose_smoke.sh`
  - `scripts/intranet_acceptance.sh`
  - `scripts/web_build_smoke.sh`

### 2.4 运行时与可观测性

- 结构化 JSON 日志
- `X-Request-ID`
- `X-Trace-ID`
- span id 写入日志字段
- request timeout 中间件
- 登录 / 密码重置分层限流
- `/metrics` Prometheus 文本输出
- `taskflow_identity_events_total`
- `taskflow_rate_limit_decisions_total`
- `taskflow_idempotency_decisions_total`
- OTLP HTTP tracing 可选接入
- `/livez`
- `/readyz`

### 2.5 数据与持久化

- memory 驱动：本地调试 / 轻量测试
- mongo 驱动：持久化与多实例共享状态
- 任务软删除
- 审计日志保留
- Mongo 版本化 migration runner

### 2.6 多实例运行时共享状态

当 `TASK_REPOSITORY_DRIVER=mongo` 时：

- 限流状态落到 `runtime_rate_limits`
- 幂等键状态落到 `runtime_idempotency_keys`
- refresh token 落到 `refresh_tokens`
- password reset token 落到 `password_reset_tokens`

这意味着：

- 限流不再局限于单进程内存
- 幂等键不再局限于单实例本地 map
- refresh token / reset token 可跨实例校验

## 4. 当前工程基线

### 4.1 目录职责

```text
taskflow/
├── cmd/
│   ├── server/                 # HTTP 服务入口
│   └── migrate/                # Mongo versioned migration 入口
├── internal/
│   ├── domain/
│   │   ├── task/               # 任务聚合、状态机、领域事件
│   │   ├── user/               # 账户聚合、Actor、Role
│   │   ├── identity/           # refresh / reset token 实体
│   │   ├── record/             # 协作记录
│   │   ├── audit/              # 审计日志
│   │   ├── event/              # 领域事件契约
│   │   └── ports/              # 仓储接口（六边形边界）
│   ├── service/                # TaskService、IdentityService
│   ├── repository/             # memory / mongo 适配器
│   ├── model/                  # HTTP DTO 与领域映射
│   ├── handler/                # HTTP handler（依赖 service / ports）
│   ├── middleware/             # auth / rate limit / idempotency / tracing
│   ├── router/                 # 路由装配
│   ├── bootstrap/              # 应用装配
│   ├── config/
│   ├── database/               # Mongo client、事务、migration 调用
│   ├── migrations/
│   └── observability/
├── scripts/
│   ├── backup_mongo.sh
│   ├── bootstrap_users.sh
│   ├── compose_smoke.sh
│   ├── intranet_acceptance.sh
│   ├── security_audit.sh
│   ├── perf_smoke.js
│   ├── restore_mongo.sh
│   ├── rollback_image.sh
│   └── web_build_smoke.sh
├── web/                        # React/Vite 最小前端工作台
├── deploy/                     # OTLP collector 示例
├── reports/                    # 安全 / 性能基线报告
└── .github/workflows/ci.yml
```

分层约定：

- `handler` / `middleware` / `router` 通过 `domain/ports` 做鉴权查询，不直接依赖 `repository` 实现
- `service` 编排领域聚合、应用领域事件、在 Mongo 模式下执行事务
- `repository` 仅实现 `ports` 中定义的接口

## 6. 这轮补齐了什么

相对上一阶段，这轮重点不是“再补几个业务动作”，而是把明显卡在生产门槛前的几项短板收口：

### 6.1 限流与幂等

此前：

- 单进程内存实现
- 多实例无法共享

现在：

- memory 模式仍保留原地可用
- mongo 模式自动切到共享存储
- 幂等键引入 `pending / completed` 状态，避免多实例重复处理同一个 key

### 6.2 账户能力

此前：

- 只有注册 / 登录 / `/me`

现在：

- refresh token
- password reset
- account disable
- revoke sessions
- disabled account 会被鉴权层拒绝

### 6.3 migration

此前：

- 只有启动时索引自举

现在：

- `schema_migrations` 记录已执行版本
- `cmd/migrate` 与服务启动都走同一套 migration runner
- 新增身份与运行时共享状态的 collection/index 也纳入版本管理

### 6.4 tracing

此前：

- 只有 request/trace id 透传

现在：

- 可选 OTLP HTTP exporter
- trace/span 上下文进入日志字段
- HTTP 请求生成 server span
- Go 1.26.4 在 OTLP 压测下出现过运行时崩溃，因此当前运行时基线已固定到 Go 1.25.11

### 6.5 交付资产与验证

此前：

- 有 Dockerfile 和部署文档，但自动化不足

现在：

- GitHub Actions CI
- 前端 `lint / test / build` 已纳入 CI
- Mongo service container + migrate smoke
- `scripts/web_build_smoke.sh`
- `scripts/intranet_acceptance.sh`
- 安全审计脚本
- k6 压测 smoke 脚本
- 本地 compose + OTLP collector 演示
- `MIGRATIONS.md` migration 纪律文档
- Docker 单机场景回滚脚本
- `INTRANET_RUNBOOK.md`、`INTRANET_OPS.md`、`ACCEPTANCE_TESTING.md`、`INTRANET_RELEASE_CHECKLIST.md`

### 6.6 最小前端与交互闭环

此前：

- 只有 API 层和 curl/Postman 级验证

现在：

- `web/` 已能完成登录、建任务、看列表、看详情、走动作流
- 任务详情页已完成组件化拆分与统一异步加载模式
- 分配动作已可通过用户下拉完成，不再依赖手填 assignee id
- 浏览器 UI 已具备演示价值，但仍保持 MVP 范围

## 7. 仍然没有完成的部分

这部分需要明确，不然会把当前仓库误判成“已经 fully production-ready”。

### 7.1 还没做完的身份能力

- 没有邮箱 / 短信等真实 reset token 投递链路
- 没有会话管理页或设备管理
- 没有 MFA
- 没有 SSO / OAuth / OIDC

### 7.2 还没做完的可观测性

- tracing 只补到了 OTLP baseline
- 没有完整 collector / backend / dashboard 拓扑模板
- 没有 RED / USE 级别的完整指标体系

### 7.3 还没做完的交付体系

- 还没有 CD pipeline
- 回滚脚本是 Docker 单机基线，不是 Kubernetes / ECS / Nomad 级自动化

### 7.4 还没做完的质量保障

- 现在有基础性能 / 安全基线报告，但还没有长时间压测或外部安全审计
- 已有一次自动化冷启动 + 备份恢复演练，但还没有跨主机或定期灾备演练

### 7.5 还没做完的前端范围

- 还没有用户管理 UI
- 还没有密码重置页面
- 还没有公开注册页面
- 还没有任务分页、搜索、附件、通知

## 8. 如果目标是“求职项目”，当前定位是什么

当前仓库已经可以展示：

- 后端分层设计
- 状态机建模能力
- 双驱动仓储抽象
- 基础认证与账户生命周期
- 中间件治理
- 可观测性基线
- migration 思维
- 最小全栈 MVP 收口能力
- 交付与回滚意识

但如果目标是把它包装成“成熟 SaaS 产品”或“Agent 协作产品第二阶段”，还差：

- 更完整的账户中心
- 更完整的前端范围与管理后台
- 更完整的 tracing / metrics / dashboard 体系
- 更真实的 CI/CD 与环境编排
- 更正式的压测与安全审计结果

## 9. DDD 分层收口（2026-06-15）

相对纯 service 内嵌规则的阶段，当前代码已推进到更接近 DDD 的分层：

| 变更 | 说明 |
| --- | --- |
| 领域包拆分 | `domain/task`、`domain/user`、`domain/identity`、`domain/record`、`domain/audit` |
| 端口层 | `domain/ports` 定义全部仓储接口；`repository` 包提供类型别名与 Mongo/Memory 实现 |
| 应用服务 | `TaskService` 负责状态机编排与事件落库；`IdentityService` 负责认证与账户生命周期 |
| 软删除 | 仅通过任务聚合 `MarkDeleted` + `Update`，删除动作写审计 |
| 数据校验 | `ParseStatus` 校验持久化状态；`userDocumentToAccount` 以 `disabled_at` 为准强制 inactive |
| 测试补充 | 新增 `identity_service_test.go`、任务分配校验测试、`ParseStatus` 单测 |

## 10. 建议的下一步

如果继续朝“可稳定交付的内网产品，再进入 Agent 二期”推进，建议优先级如下：

1. 以 `INTRANET_RELEASE_CHECKLIST.md` 为准做版本收口，保留一次完整发布证据。
2. 补剩余前端统一状态处理、关键交互测试与人工双人浏览器验收。
3. 冻结或收紧 V0 权限边界，避免后续 Agent 扩展返工。
4. 再决定是否进入 Agent 差异化阶段，优先结构化执行反馈而不是泛化多人协作。
5. 如果目标仍包含更强工程化展示，再补 CD、观测后端面板与更正式灾备演练。
