## P0

未完成前，不建议把项目称为“企业生产级”。

### P0-1 目标环境落地

- 生成并保管目标环境真实 `.env`
- 生成真实 `JWT_SECRET`
- 生成真实 `BOOTSTRAP_USERS_FILE`
- 固定真实 `APP_VERSION`
- 落实真实域名、HTTPS、反向代理和访问边界

### P0-2 试点部署与回滚演练

- 按 `INTRANET_RUNBOOK.md` 在目标内网主机完成一次完整部署
- 确认 `/readyz`、登录、任务主流程、同域入口、监控抓取都正常
- 完成一次真实备份与恢复演练，并留下记录
- 明确回滚责任人、回滚命令和回滚判定条件

### P0-3 受控发布入口

- 把当前“构建 -> migration -> 部署 -> smoke -> 回滚”固化为一条可重复执行的发布入口
- 可以是流水线，也可以是受控脚本，但不能继续依赖口头步骤拼装
- 发布入口至少要覆盖镜像版本、环境文件、迁移执行、健康检查和失败回滚
- 2026-06-26：仓库内已补 `scripts/intranet_release.sh`，剩余的是目标环境上按 Runbook 真正执行一次
- 2026-06-26：仓库内已把回滚入口统一到 `scripts/rollback_image.sh`，避免 compose 发布和回滚脚本继续分叉

### P0-4 密码重置正式链路

- 明确正式环境下密码重置令牌的投递方式
- 至少落地一条受控链路：邮件、企业 IM，或明确的人工运维流程
- 不能长期停留在 `DEV_MODE=true` 的本地回显验证方式
- 2026-06-26：仓库内已落地 webhook 投递入口，剩余的是接入真实外部投递系统并完成目标环境联调
- 2026-06-26：`STRICT_PRODUCTION_CONFIG=true` 已强制密码重置 webhook 使用 `https` 且必须配置鉴权令牌

## P1

强烈建议在试点稳定后尽快补齐。

### P1-1 会话与账号运维能力

- 增加最小可用的会话管理能力，而不只是后台 revoke
- 明确账号禁用、重建、密码重置的操作闭环
- 降低“只能靠懂系统的人手工处理”的运维依赖

### P1-2 前后端工作流规则收敛

- 当前前端在 `web/src/domain/taskWorkflow.ts` 维护了一份动作规则
- 需要避免它与后端状态机长期漂移
- 可选方向：
  - 以后端返回可执行动作作为单一事实源
  - 或增加前后端契约测试，固定动作矩阵

### P1-3 观测与告警模板

- 把 tracing、metrics、日志字段和告警规则整理成可直接复用的环境模板
- 明确哪些异常必须告警，哪些只做排障信息
- 让试点环境之外的下一套环境不需要重新摸索

## 出口标准

### 何时可称“可试点部署”

满足以下条件即可：

- P0-1、P0-2 完成
- 仓库内门禁持续通过
- 业务方确认试点范围和回滚入口

### 何时可称“企业生产级”

至少满足以下条件：

- 全部 P0 完成
- P1-1 完成
- 已有稳定的发布责任边界和运维责任边界
- 新环境可按既有文档和入口重复部署，而不是依赖特定个人记忆

## 当前建议

- 下一步优先顺序：P0-1 -> P0-2 -> P0-3 -> P0-4
- 在 P0 清完前，不建议继续扩产品功能面
- 在 P1-2 完成前，前端流程规则改动要格外谨慎，避免和后端状态机偏离
